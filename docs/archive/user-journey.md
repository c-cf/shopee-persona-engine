## 完整主流程

貼上商品連結 → 確認／補充商品資訊 → 啟動受眾分析 → 調整預選的五至十個受眾 → 生成對應文案 → 查看桌機／手機模擬商品頁 → 比較、修改、標記喜歡 → 複製選定版本文字或單頁 JSON。

預覽後可返回「探索受眾」取消或新增勾選，再按「更新商品頁」套用五至十個方向。保留原有版本的改稿與喜歡標記；暫時取消的受眾再次勾選時恢復原版本。「複製此頁 JSON」只包含當前頁的最新標題、文案、商品資訊及受眾，供後續使用。

下表整理已確認的操作順序與畫面責任；「對應規則」欄已於第三輪確認。階段不強制對應獨立頁面。

| 階段 | 賣家看到什麼 | 操作與系統回應 | 對應規則 |
| --- | --- | --- | --- |
| 1. 帶入商品 | 商品連結輸入欄、手動補充入口 | 貼上連結，服務讀取商品內容 | 讀取失敗、最低必要資料（Q9） |
| 2. 確認商品 | 原圖、現有標題、價格、規格、描述 | 檢查並修正資料，啟動分析 | 缺圖或缺價時如何繼續（Q9） |
| 3. 查看分析 | 逐步出現的受眾、來源組別與進度 | 閱讀已完成結果，三十秒出現第一批為目標 | 未滿十五個時如何繼續（Q10） |
| 4. 選擇方向 | 受眾總覽、五個預選方向、選取數量 | 調整並確認五至十個受眾 | 新結果如何影響既有選擇（Q10） |
| 5. 生成文案 | 各選定受眾的生成狀態 | 生成標題、賣點與描述，預覽逐張出現 | 部分失敗與重試（Q10） |
| 6. 查看預覽 | 商品圖、標題、價格、規格與完整文案 | 切換版本與桌機／手機呈現 | 單頁與並排比較的切換（Q12） |
| 7. 比較與修改 | 候選版本與文字編輯入口 | 修改標題／文案，標記喜歡的版本 | 比較基準、修改保留與還原（Q12） |
| 8. 帶走成果 | 選定版本的標題與文案 | 複製可用文字，完成本次核心任務 | 保存與回訪方式（Q11） |

## 版本與商品的關係

- 一次分析針對一項商品，商品資料是各文案版本共同依據。
- 一個選定受眾對應一個文案版本與模擬商品頁；五至十個版本的差異來自受眾、標題、賣點排序與描述。
- 桌機與手機是同一版本的呈現方式，不增加交付版本數量。
- 各版本共用原商品圖片、價格與規格，生成文案不改變商品事實。
- 受眾詳情用來理解推薦，模擬商品頁用來查看文案的實際呈現。
- 部分預覽先出現屬於漸進交付；完整交付仍以五至十個頁面為目標。

## 完成判準

1. 賣家可貼上商品連結，確認並補充資料後開始分析。
2. 正常完整分析提供三組共十五個受眾；賣家可調整五至十個選定方向。
3. 每個選定受眾有一個對應版本，能看出該版本面向誰。
4. 五至十個模擬商品頁皆包含商品圖、標題、價格、規格與完整文案，並支援桌機／手機呈現。
5. 賣家可以比較、修改、標記喜歡的版本並複製成果；商品事實在各版本間一致。
6. 首批受眾三十秒、首批五個預覽兩分鐘的目標，需以實測記錄驗證。

資料缺漏、受眾不足或生成失敗時，如何判定部分可用與本輪完成，依 Q9–Q10 處理。

## 設計觀察

1. 賣家可感受到的價值是找到值得採用的受眾與溝通方式；10K Personas 與三條引擎屬於背後的生產與分析流程。
2. 已確認服務內生成與模擬預覽；生成成本、候選版本管理與失敗恢復將由服務流程承接。
3. 已區分「受眾建議」「文案版本」「模擬商品頁」。五至十個交付物指模擬商品頁，每個選定受眾對應一個版本。
4. 真實評論支持某種需求，不等於已證實該受眾會在 Shopee 購買目前商品；Explorer 的故事與 uplift 分數也需要明確的證據語義。

## 決策樹

Q1–Q12 均已確認。以下第三輪建議已採納，次要細節依第一版需要直接處理。

- Q9：商品資料不完整時，怎樣讓賣家繼續？（依賴 Q4、Q6）
  - 建議：至少提供商品名稱與可核對的用途／規格／描述，便可開始分析。讀取失敗時允許手動輸入商品內容與提供原圖。
  - 缺圖顯示佔位、缺價標示未提供，可先分析與生成文字；補齊後才算完整預覽。未知的圖片、價格、規格、評價與銷量不自動編造。
  - 後續檢查：若已確認的商品事實被修改，需要標記舊分析過時並重新分析，保留舊結果供辨識。
- Q10：引擎未跑完或個別預覽失敗時，流程如何繼續？（依賴 Q5、Q8）
  - 建議：已有五個合格、不同的受眾方向，即可選擇並開始生成，其他引擎繼續執行；新增結果不更動使用者既有選擇。
  - 五個預選方向基於當時可用結果，介面標示其餘組別是否仍在分析。少於五個則保留結果，提供補資料或重試入口，等足五個再生成。
  - 預覽部分失敗時，先顯示可用頁面，只重試失敗項目，保留成功內容與手動修改；交齊選定版本才顯示整批完成。
  - 受眾詳情需區分 Core 商品契合、Market 評論佐證、Explorer 探索假說，讓選擇依據可理解。
  - 此方案維持原規劃 Explorer 完整 10K 推論的範圍；完整三組的總耗時需另行量測。三十秒與兩分鐘仍是待驗證目標。
- Q11：登入、保存與回訪需要做到哪裡？（依賴 Q7、Q8）
  - 建議：第一版免登入，分析與預覽自建立起保存七天，同一瀏覽器可回訪，自動保存選擇、文字修改與喜歡的標記；重新整理或暫時離開後能恢復進度與已有結果。
  - 顯示到期時間，到期後移除該次分析與預覽；跨裝置與團隊共用未列入提案。這是保存政策提案，儲存技術尚未選定。
- Q12：如何比較與修改，才方便挑選？（依賴 Q6、Q7）
  - 建議：桌機一次並排兩個版本，可用原商品內容作為對照；手機逐一切換。修改標題／文案後即時更新預覽，保留最初生成文字並提供還原操作。
  - 喜歡的標記可套用到多個版本；複製的是目前修改後的文字。原商品對照與同一版本的編輯不另計為新交付頁面。

使用者已確認整體方向並要求儘速看到第一版，直接開始實作，略過剩餘細節。第一版實際涵蓋範圍與示範資料限制見 README.md 及 ADR-0002；研究引擎的效能目標尚未以真實模型驗證。

- 前端與後端以 TypeScript 為規劃基準，共用商品、分析進度、受眾與交付物的資料契約。
- Q8 已確認等待目標。Explorer 大量推論的成本與總耗時仍需驗證；第一版已安排背景工作、進度保存與重試。
